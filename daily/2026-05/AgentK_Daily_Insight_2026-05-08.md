## 1. 에이전트가 이제 Cloudflare 계정을 만들고, 도메인을 구매하고, 배포할 수 있음
링크: https://news.hada.io/topic?id=29249

[핵심 요약]
Cloudflare와 Stripe가 함께 설계한 새 프로토콜을 통해 코딩 에이전트가 Cloudflare 계정 생성, 유료 플랜 시작, 도메인 등록, API 토큰 발급, 프로덕션 배포까지 수행할 수 있게 됐습니다. 사람은 권한 승인과 약관 동의 정도만 맡고, 실제 인프라 준비 절차는 에이전트가 끝까지 이어받는 구조입니다.

[기술적 인사이트]
이 변화의 본질은 "에이전트가 코드를 쓰는 단계"를 넘어 "에이전트가 공급자 온보딩과 결제까지 처리하는 단계"로 넘어갔다는 데 있습니다. Discovery·Authorization·Payment를 프로토콜로 분리한 점은 향후 다른 클라우드/도메인/결제 공급자까지 표준화될 가능성을 보여줍니다. 다만 비용 상한, 자격증명 범위, 공급자 종속성, 잘못된 자동 구매 시 책임 소재를 함께 설계하지 않으면 운영 자동화가 곧바로 재무·보안 리스크로 번질 수 있습니다.

## 2. Google Cloud Fraud Defense, reCAPTCHA의 다음 진화 단계
링크: https://news.hada.io/topic?id=29237

[핵심 요약]
Google Cloud는 reCAPTCHA를 확장한 Fraud Defense를 출시하며, 봇뿐 아니라 사람·AI 에이전트까지 구분하고 정책적으로 제어하는 "에이전트형 웹 신뢰 플랫폼"을 제시했습니다. 기존 reCAPTCHA 사용자는 별도 마이그레이션 없이 그대로 이 체계에 편입됩니다.

[기술적 인사이트]
앞으로의 보안 제품은 단순 요청 차단보다 "누가 어떤 자동화 주체로 행동하는가"를 판별하는 방향으로 움직일 가능성이 큽니다. 위험 점수, 자동화 유형, 에이전트 신원, 사용자 개입 여부를 결합한 정책 엔진은 로그인·결제·체크아웃 전 구간을 하나의 리스크 모델로 묶으려는 시도입니다. 반면 QR 기반 인간 개입 검증은 모바일 의존성과 폐쇄형 플랫폼 의존을 강화할 수 있어, 보안 강화와 사용자 자율성 사이의 긴장이 더 커질 전망입니다.

## 3. Supabase에서 Clerk를 거쳐 Better Auth로
링크: https://news.hada.io/topic?id=29235

[핵심 요약]
Val Town은 사용자·세션 상태를 외부 인증 SaaS에 깊게 의존한 구조의 한계를 겪은 뒤, Clerk에서 Better Auth로 전환했습니다. 특히 사용자 테이블 동기화 복잡성과 세션 갱신 경로의 외부 의존성이 핵심 문제로 지목됐습니다.

[기술적 인사이트]
이 사례는 "인증을 외주화하면 편해진다"는 통념이 어디까지 유효한지 잘 보여줍니다. 로그인 자체보다 더 무거운 문제는 사용자 프로필, 권한, 세션 갱신, 장애 전파 같은 상태 관리의 경계가 흐려지는 순간 발생합니다. 소셜 기능이 있거나 여러 사용자의 데이터를 자주 노출하는 제품이라면, 인증 제공자와 내부 DB가 이중 권위 체계가 되기 쉽습니다. 결국 핵심 세션 상태는 가능한 한 애플리케이션이 직접 통제하고, 외부 서비스는 보조 기능으로 한정하는 설계가 다시 힘을 얻을 가능성이 큽니다.

## 4. 오픈 가중치가 조용히 닫히고 있으며, 이는 문제다
링크: https://news.hada.io/topic?id=29256

[핵심 요약]
오픈 가중치 모델은 온프레미스 실행, 파인튜닝 유연성, 낮은 추론 비용으로 폐쇄형 프런티어 모델에 강한 가격 압력을 줘왔지만, 최근 일부 연구소가 공개 범위를 줄이거나 라이선스를 강화하는 흐름이 나타나고 있습니다.

[기술적 인사이트]
오픈 가중치의 의미는 단지 "개발자가 로컬에서 돌릴 수 있다"에 그치지 않습니다. 이것은 폐쇄형 모델 사업자에게 사실상의 가격 상한선을 만드는 시장 장치이기도 합니다. 공개 모델 공급이 줄어들면 기업은 데이터 주권·비용 최적화·대체 가능성 세 축에서 동시에 협상력을 잃게 됩니다. 특히 에이전트형 워크로드처럼 대량 추론이 필요한 환경에서는 모델 성능 격차보다 비용 구조와 배포 자유도가 더 중요해질 수 있어, 오픈 가중치 축소는 중장기적으로 산업 집중도를 키우는 신호일 수 있습니다.

## 5. Go가 FIPS 140-3 인증을 받음
링크: https://news.hada.io/topic?id=29245

[핵심 요약]
Go Cryptographic Module이 NIST CMVP 기준 FIPS 140-3 인증을 받았습니다. 이제 일부 정부·방산·규제 산업에서 Go를 채택할 때 가장 큰 제약 중 하나였던 컴플라이언스 장벽이 낮아질 수 있습니다.

[기술적 인사이트]
중요한 포인트는 이번 인증이 순수 Go 기반 경로를 강화한다는 점입니다. 과거처럼 OpenSSL/Boring 계열 우회 구성에 기대지 않고 표준 라이브러리 중심으로 규제 대응 스토리를 만들 수 있으면, 배포 복잡도와 운영 리스크가 모두 줄어듭니다. 즉 성능 개선 뉴스라기보다, Go가 "규제 산업에서도 조직 표준 언어가 될 수 있는가"에 대한 대답에 가까운 변화입니다.

## 6. SQLite는 미국 의회도서관 권장 저장 형식임
링크: https://news.hada.io/topic?id=29264

[핵심 요약]
SQLite가 미국 의회도서관의 데이터셋 권장 저장 형식군에 포함된다는 점이 다시 주목받았습니다. 공개성, 채택도, 투명성, 자기 문서화, 외부 의존성 같은 장기 보존 기준에서 높은 평가를 받는다는 의미입니다.

[기술적 인사이트]
이 소식이 시사하는 바는 단순한 "SQLite 예찬"보다 큽니다. 파일 하나로 옮길 수 있고, 스키마와 데이터를 함께 유지하며, 특정 서비스에 묶이지 않는 저장 형식은 AI 시대에도 여전히 강력합니다. 특히 장기 보존, 감사 추적, 엣지 배포, 오프라인 우선 앱에서는 중앙 서버형 DB보다 SQLite 같은 포터블 데이터 포맷이 더 전략적일 수 있습니다. 데이터 인프라가 다시 "이식성"과 "수명"을 중시하는 방향으로 돌아오고 있다는 신호로 읽힙니다.
